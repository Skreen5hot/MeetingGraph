## Findings

1. **The invitations item came back partial in every run.** The question asked two things ("were they sent, and did James receive his?"), and the meeting stated only receipt. The model was right to be strict. Under the closure rule a partial answer is never offered for closing, so this item would stay open even though, in practice, it was answered.
   - **Fix:** ask one thing per question ("Did James receive the invitation?").
   - This is a question-wording lesson, not a model failure.
2. **New flags duplicate open items.** Runs 1 and 2 also raised a *new* implied_change flag on AI-203/AI-207 for the same unconfirmed dates. In the build, that would create a second label for a question that is already open.
   - **Fix (rule text):** "When you give a partial answer, do not also flag the same question."
   - **Fix (backstop in the build):** a new flag from the same meeting is not shown as a new item when it has the same kind and records as an open item that this reply answered partially.
3. **The `match` field was used on an owner question.** Runs 1 and 2 added `"match": "alvarez"` there. It is harmless, since the validator ignores `match` for owner questions. Tighten the rule text: `match` is only for who-is questions.
4. **Unrelated to open items:**
   - Run 3 did not create a task for the hardware list. It read "I can do that" as an uncertain commitment, an existing rule-4 behavior.
   - All runs flagged AI-203 and AI-404 as overdue.

The checker was corrected during scoring: it had required "answered" for the invitations item, although the scoring sheet accepts "partial". The self-test stays green.
